Interests (the toolchain)

Fun fact / current side quest

I'm building a multi-agent system for incident management and automation, exploring how AI agents can collaborate to investigate incidents and streamline operational workflows.

AI in software engineering today

AI is changing how we write and maintain software, and it's already making developers more productive. However, generating code is only one part of software engineering. Understanding the system, making architectural decisions, debugging, and ensuring reliability and security still require strong engineering fundamentals. I see AI as a powerful engineering assistant, not a replacement for engineering knowledge.

Software engineering in 5–10 years

I think software engineering will move towards more autonomous, AI-driven workflows, where developers orchestrate agents that can build, test, deploy and monitor applications. The role of engineers will increasingly shift from writing every line of code to designing systems, defining constraints and validating outcomes. Cloud, DevOps and AI will become even more interconnected.

Hot take, fresh from the pipeline

“The future belongs to engineers who know what to automate and, more importantly, what not to.”

AI in software engineering today

AI coding agents are great for boilerplate, quick scripts and explaining unfamiliar code. But they still make confident mistakes, so every change needs to be reviewed and tested. Right now they are a strong assistant, not a replacement for understanding the system.

Software engineering in 5–10 years

Engineers will spend less time typing code and more time specifying, reviewing and verifying what agents produce. Domain knowledge, for example in electrical and embedded systems, will matter even more, because someone has to judge whether the generated solution is actually correct and safe.

AI in software engineering today

AI is great at boilerplate, glue code and getting unstuck, and it has made me noticeably faster. But it's confidently wrong often enough that you still need to understand every line it writes. The bottleneck has shifted from typing code to reviewing it, and most teams haven't adjusted for that yet.

Software engineering in 5–10 years

Engineers will spend more time specifying, reviewing and testing than writing code by hand, with agents handling much of the implementation. The valuable skills will be system design, knowing the domain, and judging whether the output is actually correct. Codebases will grow faster than anyone can read them, so testing and observability will matter more than ever.

AI in software engineering today

Software engineering has already changed a lot: most code is now written by agents, and humans act largely as validators. Still, coding agents struggle to understand requirements and to produce well-structured code (for example, following OOP principles), so human supervision remains necessary.

Software engineering in 5–10 years

Software engineering will change rapidly. Coding agents are getting better at generating complex code and understanding user requirements from only a few prompts. Humans will increasingly move into a supervisory role, reviewing the work agents do, which means faster development timelines and fewer human resources.

Hot take, supervisor's cut

“Developers won't be replaced by AI, but developers who don't supervise it well will be replaced by those who do.”

The group project answer

AI gets the keyboard. Engineers keep the judgement.

Our shared view: AI is already useful for producing code, handling boilerplate, speeding up workflows and helping people get unstuck. In the next 5–10 years, agents will likely do more of the implementation—and may build, test, deploy and monitor whole applications—while engineers spend more time setting direction, designing systems, specifying constraints, reviewing, testing and validating results.

We agree that engineering fundamentals and domain knowledge still matter: confident output can be wrong, poorly structured, unreliable or unsafe. As code gets generated faster, verification, testing, observability and knowing what not to automate become more important, not less.

Where we differ: Namit sees AI as already unmatched at writing code and expects it to write most code; Gagan says most code is already agent-written and humans largely validate it. Soumya, Sarpesh and Ranjith stress its strengths as an assistant today, alongside today’s mistakes and limits. The shared destination is similar; the “how far along are we?” marker is in different places.

Translation: fewer keystrokes, more judgement—and nobody gets to ship a mystery diff just because the bot sounded confident.
